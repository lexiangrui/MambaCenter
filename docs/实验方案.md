# 实验方案

2026-10-24 起的全部 CenterNet 系实验使用同一训练方案（[configs/_base.yaml](../configs/_base.yaml)），模型之间只差 arch、模型参数与辅助损失权重。此前的 CenterNet / CenterMamba / CGM 结果已丢弃，不作比较；Mamba-YOLO-B 保留原结果。

## 运行清单（第一批，seed 317）

| 运行 | 配置 | 对比 | 回答的问题 |
|---|---|---|---|
| centernet_dla34_s317 | 原版 CenterNet（DLA-34 + DCNv2） | — | 基线 |
| mambafpn_s317 | 普通 VSS 颈部（A1） | vs 基线 | Mamba 颈部本身的作用 |
| cpmamba_b1_s317 | A1 + P3 粗热图辅助监督（B1） | vs A1 | 粗热图多任务增益 |
| cpmamba_s317 | CP-Mamba（B5） | vs B1 | CP-SSM 去留判断 |
| iamamba_s317 | IA-Mamba（A4） | vs A1 | IA-SSM 去留判断 |

两份设计文档的主战场是 AI-TOD；本项目当前只有 VisDrone，先在 VisDrone 上做去留判断。

第一批结果（val AP@100，最后一轮）：基线 26.40；A1 23.65、B1 23.35、B5 23.26、A4 23.80。
四个 Mamba 颈部变体都比基线低 2.6–3.1 AP，B5−B1 和 A4−A1 都没有增益。差距来自整个替换 DCN 颈部：
- Mamba-FPN 只有 1.17M 参数、没有 DCN；DLAUp+IDAUp 有 3.94M 参数和 16 个 DCN，其中 5 个在 stride 4。
- 旧的普通卷积 DLA 颈部（70 轮）已高于 Mamba-FPN。
- 旧的外挂式 CenterMamba 比它自己的基线高 0.34。

## 第二批：DCN 颈部外挂（seed 317）

保留原版 CenterNet 的 DLAUp/IDAUp，把 Mamba 块作为残差外挂（[mambacenter/addon.py](../mambacenter/addon.py)），接在两处：
- stride 8：DLAUp 的 P3（128 通道），在最后的 IDAUp 之前；
- stride 4：IDAUp 输出（64 通道），在检测头之前。

两处各 2 个块，每块是 SS2D 混合器加 FFN（mlp_ratio 4），两个分支的末端投影都零初始化。所以初始化时检测器与 DCN 基线完全一致：tests/test_addon.py 在 CPU 上验证；GPU 上把训练好的基线权重装进四个外挂模型，fp32 和 bf16 下输出都与基线一致。

| 运行 | 配置 | 对比 | 回答的问题 |
|---|---|---|---|
| addon_vss_s317 | 外挂普通 VSS（A1′） | vs centernet_dla34_s317 | 外挂 Mamba 本身有没有增益 |
| addon_cp_b1_s317 | A1′ + stride-8 粗热图辅助监督（B1′） | vs A1′ | 粗热图多任务增益 |
| addon_cp_s317 | stride 4 换成 CP-SSM（B5′） | vs B1′ | CP-SSM 去留 |
| addon_ia_s317 | 两处都是 IA-VSS（A4′） | vs A1′ | IA-SSM 去留 |
| addon_ia_a5_s317 | A4′ 去掉下界（A5′）：Δ = softplus(Wx + b + γ(aE + c)) | vs A4′、A1′ | 允许 Δ 被压低后，调制是否起作用 |

加跑 A5′ 的原因：A4′ 训练到第 56 轮时，三个会被调制的块里 γ 的原始值都变成了负数（−0.20 / −0.05 / −0.16），前向时被下界截成 0，Δ 调制实际上被关掉了，只剩"创新图进热图头"这一条路在起作用。A5′ 中 γ 仍要求 ≥ 0，但 a、c 不受限制，aE + c < 0 的位置 Δ 会被压低。

第二批结果（val AP@100，第 140 轮；括号内为第 100–140 轮五次评测的均值）：
- 基线 26.40（26.33）；A1′ 27.34（27.47）；B1′ 27.68（27.56）；B5′ 27.95（27.97）；A4′ 27.77（27.84）；A5′ 27.98（28.06）。
- 外挂 Mamba：A1′ 比基线 +0.94，14 次评测全部高于基线。
- CP：B5′ − B1′ = +0.27（五次均值 +0.41），B1′ − A1′ = +0.34（均值 +0.09）。α 停在 1.18 / 0.99。
- IA：A4′ − A1′ = +0.43（均值 +0.37），A5′ − A1′ = +0.64（均值 +0.59），A5′ − A4′ = +0.21。
- 但 Δ 调制基本没有起作用：A4′ 三个受调制块的 γ 原始值都是负数（−0.33 / −0.10 / −0.30），被下界截到 0；A5′ 有两个块为负（−0.28 / −0.06），只有 stride-4 第二块 γ = 0.014。IA 的增益主要来自创新图进热图头（hm_innov 权重均值 0.034，与热图头第一层 0.022 同量级）。
- 只有一个 seed；第一批中名义上无差别的 B1 − A1 为 −0.30，所以 0.3 左右的差值不能当作结论。

训练方案与第一批完全相同（configs/_base.yaml），基线直接沿用 centernet_dla34_s317，不重跑。外挂新增参数的学习率为共享 lr 的 5 倍（`train.new_lr_mult`）；骨干、DLA 颈部和检测头与基线同一 lr。

机制上的改动：
- CP：α 初值 1.0，与优先路由共用 warm-up 和淡入。第一批 α 从 0 起步，只学到 0.12。
- IA：开启 `cross_level`，两个 stride-4 块都受调制。第一批的 P2 从未受过调制。

显存：外挂块逐块重算时，每次只处理 5 张图（`micro_batch: 5`）。块内运算都是逐图的，所以结果不变（测试验证输出和梯度一致），整体仍是 batch 20。不切分时，batch 20 下普通 VSS 外挂峰值 28.2 GiB，IA 外挂显存不足。

切分后的探测结果（检查作业 161814，RTX 5090，bf16，完整训练步）：

| 配置 | 参数（新增） | B=16 | B=20 | B=24 | 吞吐 |
|---|---:|---:|---:|---:|---:|
| addon_vss（A1′） | 20.38M（0.73M） | 16.6 | 21.6 | 24.9 | 14.0 |
| addon_cp_b1（B1′） | 20.53M（0.87M） | 16.1 | 19.2 | 23.0 | 13.9 |
| addon_cp（B5′） | 20.52M（0.87M） | 15.4 | 19.2 | 23.0 | 15.0 |
| addon_ia（A4′） | 20.53M（0.87M） | 17.8 | 21.0 | 24.1 | 11.6 |

显存单位为 GiB，吞吐为张/秒。外挂的吞吐约为 DCN 基线（29 张/秒）的一半，140 轮约 17–22 小时。

## 集群约束（2026-10-24 查询）

- RTX 5090（32 GB，sm_120）在 gpu01/02/04/05 与 debug01；gpu01/04/05 被其他用户预约到 11-11/12，gpu02 与 debug01 共享且基本满载；gpu03 为 16 GB RTX 5080。
- 单卡作业上限 25 CPU / 32G 内存。因此每个实验用 1 张 5090、12 CPU、32G，申请 `gpu:nvidia_geforce_rtx_5090:1` 避免落到 16 GB 卡，分区 batch 或 debug01 先到先用。

## 训练方案

| 项 | 取值 | 依据 |
|---|---|---|
| 输入 | 训练 960×960 随机尺度裁剪（CenterNet 0.6–1.3 倍 + 翻转 + 颜色增强）；测试长边 960（fix_res） | val 图像多为 1360×765，测试缩放 0.71 落在训练尺度范围内；与保留的 Mamba-YOLO（960）同尺度 |
| 每卡 batch | 20 | 所有模型都能放下的最大公共 batch（IA-Mamba 峰值 27.8 GiB，占 31.4 GiB 的 89%）；同一 batch 保证可比 |
| 优化器 / 学习率 | Adam，lr = 5e-4 × 20 / 128 = 7.8125e-5，无权重衰减 | CenterNet 官方线性缩放规则（128 张对应 5e-4） |
| 轮数 / 学习率计划 | 140 轮，第 90、120 轮后 ×0.1；前 500 次迭代线性 warm-up | CenterNet 1x 计划；warm-up 保护随机初始化的 Mamba 颈部 |
| 精度 | bf16 autocast；扫描、投影、Δ、损失、评测为 fp32 | 5090 张量核；bf16 不需要 loss scaling |
| 显存 | Mamba 颈部逐块 activation checkpoint（数值不变，tests/test_models.py 校验） | 不开时 batch 16 下 Mamba-FPN 峰值 28 GiB、IA-Mamba 超出 32 GB |
| 数据 | max_objs 1000（覆盖 train 单图最多 902 个目标）；8 个 loader 进程，作业 12 CPU / 32G | 原 500 会把 2 张图的 414 个目标变成负样本；8 进程供数约 160 张/秒，高于最快模型的 30 张/秒 |
| 评测 | 每 10 轮及最后一轮在 val 上评测；报告最后一轮，不按 val 选最优 | 避免在报告集上挑 checkpoint |

## 评测口径

VisDrone2019-DET val（548 张），转换后的 COCO 标注（过滤 ignore/others），不等同于官方忽略区域协议。
CenterNet 解码 top-500，原图坐标，分数保留全精度；COCOeval 同时给出 maxDets=100（与 Mamba-YOLO 的保留结果同口径）和 maxDets=500（VisDrone 口径）的整体 AP / AP50 / AP75。
